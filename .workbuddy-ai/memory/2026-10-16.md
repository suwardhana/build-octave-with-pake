## Brainstorm plugin Octave Music (macOS / Pake wrapper)

Dhana minta ide plugin tambahan untuk app desktop macOS. Konteks yang dikonfirmasi dari
dokumentasi resmi Pake (`schema/pake.schema.json` + `docs/advanced-usage.md`):

- `inject` = array path CSS/JS lokal. **Tier 1 (inject-only)** = tambah file + 1 baris di
  `app.json`, rebuild `pake --config app.json --install`. Nol fork.
- **Tier 2** = butuh command native baru -> WAJIB fork Pake: daftar di `generate_handler!`
  + command manifest `src-tauri/build.rs` + permission di `capabilities/default.json`.
- Tersedia tanpa fork: `window.__TAURI__.core.invoke` (command bawaan), Web `Notification` API
  (Pake map ke notif native macOS), `activationShortcut`, `multiWindow`, `alwaysOnTop`,
  `downloadDir`, `enableFind`, `restoreLastUrl`.
- IPC dibatasi ACL ke origin yang dikonfigurasi; redirect login/origin lain tidak dapat
  permission native.

### Kandidat plugin (belum ada di src/js/)

- `octave-nowplaying.js` — `mediaSession.metadata` + `setPositionState` (cover + progress bar
  di Control Center). Sekarang `octave-media.js` cuma benerin prev/next. **S**
- `octave-sleeptimer.js` — stop N menit / akhir lagu / N track + fade-out. Fade WAJIB pakai
  nilai UI karena volume sudah dipatch `v**3` di `octave-volume.js`. **S**
- `octave-notify.js` — notif macOS saat ganti lagu. **S**
- `octave-eq.js` — 10-band EQ + preset via Web Audio. RISIKO: `createMediaElementSource` butuh
  `crossOrigin` di-set SEBELUM `src`, kalau tidak output bisa senyap. **M**
- `octave-loudness.js` — normalisasi loudness antar track (ReplayGain-ish). **M**
- `octave-offline-panel.js` — panel cache lossless, baca `localStorage.__octave_audio_index_v1`
  yang sudah diisi `octave-cache.js`. **M**
- `octave-save-track.js` — export lossless ke disk via blob + `<a download>`. **S**
- `octave-miniplayer.js` — mode compact CSS-only (hide sidebar, sisakan player bar). **M**
- `octave-shortcuts.js` — layer shortcut sendiri (`disabledWebShortcuts: true` sudah aktif). **S**
- `octave-theme.js` — light theme + ikut Appearance macOS (sekarang `darkMode: true` hardcoded). **M**
- `octave-lyrics.js` — overlay lirik sinkron dari LRCLIB (gratis, tanpa API key). **M**
- `octave-scrobble.js` — Last.fm scrobble. **M**
- `octave-webhook.js` — POST now-playing ke Discord webhook (alternatif murah dari RPC). **S**
- `octave-diag.js` — panel diagnostik + ring buffer `console.error` + copy bug report markdown. **S**
- `octave-plugin-host.js` — refactor 9 inject jadi registry `{id, init, health()}` + toggle UI. **M**
- Tier 2 (fork): Discord Rich Presence, media key global saat app tidak fokus, tray/Dock menu dinamis.

### Urutan usulan

nowplaying -> offline-panel + save-track -> sleeptimer -> eq -> plugin-host -> diag

Dhana pilih grup **Library & offline** -> ditulis `plan-plugins.md` (root repo, format sama
kayak `plan-android.md`).

Isi plan: `octave-offline-panel.js` (panel manajer cache: ringkasan + daftar track + pin +
rekonsiliasi drift + preset budget) dan `octave-save-track.js` (ekspor lossless ke disk via
blob + `<a download>`, trigger `⌘⇧S`). Plus `octave-shared.js` untuk util bersama.

Keputusan teknis yang dikunci di plan:
- Metadata lagu TIDAK disimpan di index cache (index cuma `{track, bytes, ts}`), jadi panel punya
  map sendiri `__octave_track_meta_v1` + backfill lewat endpoint `meta/batch` situs.
- Pin anti-evict butuh patch ~8 baris di `octave-cache.js` (`enforceAudioBudget` skip entri pinned).
  Ini satu-satunya perubahan ke modul lama; sisanya nol sentuh.
- Budget jadi preset lewat `localStorage.__octave_budget_v1`.
- `app.json` ditambah `downloadDir: ~/Music/Octave` (perlu diverifikasi apakah berlaku untuk blob
  download di WKWebView).
- Risiko utama: CORS header di audio CDN. Kalau tidak ada, ekspor hanya bisa untuk lagu yang sudah
  di-cache. Fase 0 (discovery) wajib duluan karena menentukan desain.

Catatan integrasi penting yang ditemukan: `disable-right-click.js` blokir `contextmenu` kecuali
target cocok selector tertentu -> jangan pakai right-click untuk baris panel. `octave-depin.js` +
`octave-native.js` punya MutationObserver global -> panel harus build DOM sekali, update lewat
`textContent` saja, biar tidak memicu badai TreeWalker.

## Hasil Fase 0 masuk + Fase 4 dikerjakan

Dhana jalankan `tools/fase0-discovery.js` di Chrome dan kirim laporannya.

### Temuan penting

1. **CORS ternyata AMAN — probe versi pertama salah.** Halaman di `music.octavestreaming.com`,
   audio di `api.octavestreaming.com` (cross-origin), tapi `fetch()` resolve (status 206) dan
   bahkan bisa baca `content-range`. Kesimpulan awal "ACAO tidak ada -> CORS gagal" itu **false
   negative**: header `Access-Control-Allow-Origin` dikonsumsi browser dan TIDAK PERNAH bisa
   dibaca dari JS. Sudah diperbaiki di probe; catatan metodologinya ditulis di plan §1b.a dan
   MEMORY.md.
2. **Metadata ada di URL audio.** `?track=<id>&t=<title>&a=<artist>&d=<durasi>&x=<0|1>&k=<token>`.
   Jadi tidak perlu endpoint meta sama sekali. Rencana backfill `/api/tracks/features` dibatalkan.
3. **Token `k=` punya masa berlaku** -> URL audio jangan disimpan, simpan trackId + metadata saja.
4. **Situs SUDAH punya offline store sendiri**: cache SW `octave-v8-static/pages/rsc/img/data`
   (86/26/265/784/209 entri) + route `/library/downloaded`. Ini pertanyaan desain yang belum
   dijawab — panel kita bisa jadi duplikasi. Dijadikan Fase 3a (blocker untuk panel).
5. `octave-static-v1` (cache cover kita) redundan dengan `octave-v8-img`.
6. `mediaSession.metadata` TERISI lengkap (title/artist/album/artwork 4 ukuran).
7. Endpoint yang bikin ide plugin lain gugur: `POST /api/lyrics` (lirik sudah ada di situs),
   `GET /api/lastfm/status` (Last.fm sudah terintegrasi). Juga ada `/api/ios/release` (app iOS resmi)
   dan `/api/apple/*` (integrasi Apple Music).
8. Storage di Chrome: usage 69.3 MB, quota 10.1 GB, persisted true.

### Yang dikerjakan

- `tools/fase0-discovery.js` — probe CORS diperbaiki (jangan percaya header ACAO, patokan =
  fetch resolve/reject). Ditambah bagian [7] metadata URL + [8] ringkasan.
- `src/js/octave-shared.js` — tambah `parseAudioUrlMeta`, `pickExtension`, `sanitizeFilename`,
  `buildFilename`. Total 12 fungsi + 6 konstanta.
- `src/js/octave-save-track.js` — BARU, Fase 4. Ekspor lagu ke disk. Cache-first (nol network
  kalau sudah di cache), cache-miss pakai `window.fetch` yang sudah dipatch `octave-cache.js`
  (sekali unduh, sekalian masuk cache) + progress dari `res.body.getReader()`. Handle jebakan
  `dataset.octaveOrigSrc` (octave-cache.js mengganti src jadi blob URL untuk track ter-cache).
  Toast dibangun sekali (MutationObserver global). `revokeObjectURL` ditunda 60 detik.
- `app.json` — `downloadDir: ~/Music/Octave` + `octave-save-track.js` di inject.
- `tools/check-octave-plugins.js` — 35 pemeriksaan (naik dari 21).
- `plan-plugins.md` — ditulis ulang besar-besaran: section §1b "Hasil Fase 0", §2.2-§2.6 direvisi
  dan ditandai SELESAI, Fase 3 dipecah jadi 3a (telusuri /library/downloaded) + 3b, §7 risiko
  diperbarui (baris CORS ditandai gugur), §9 ditambah "ide yang gugur".
- `readme.md` — struktur file, bagian "Simpan lagu ke disk", jumlah pemeriksaan 21 -> 35.

## Bug: "Tidak bisa membaca id track dari URL audio"

Setelah rebuild + klik tombol, Dhana dapat toast error itu. Toast-nya muncul -> tombol dan plugin
jalan, yang gagal cuma resolusi URL.

### Penyebab

`currentTrackUrl()` versi pertama menerima **URL apa pun** dari elemen `<audio>`/`<video>`,
termasuk yang tidak punya parameter `track`. Kalau situs punya elemen media lain (preloader,
analyser) atau mengalirkan audio lewat MediaSource (src = blob:), yang keambil adalah URL yang
salah -> `parseAudioUrlMeta` mengembalikan `trackId: null`.

### Perbaikan

Resolusi URL sekarang berlapis, dan kandidat tanpa id track DIBUANG (bukan dipakai sebagai
upaya terakhir — itu cuma menyamarkan penyebab):

1. elemen `<audio>/<video>` — hanya kalau punya id track
2. `dataset.octaveOrigSrc` (kalau `octave-cache.js` sudah menukar src jadi blob:)
3. rekaman URL `/audio/lossless` dari **PerformanceObserver** dengan `buffered: true`

Lapis 3 pakai `PerformanceObserver`, BUKAN `performance.getEntriesByType`, karena buffer resource
timing terbatas (default 250 entri) sementara situs ini punya 784 entri gambar di Cache Storage —
buffer bisa penuh dan entry baru berhenti tercatat. Observer merekam dari awal dan terus jalan.
Pemilihan: cocokkan `t` di URL dengan `mediaSession.metadata.title`; kalau tidak ada yang cocok,
ambil yang paling baru. Plus `performance.setResourceTimingBufferSize(1000)` sebagai jaring ekstra.

### Perubahan lain

- **Pesan error sekarang membawa bukti.** Toast gagal menyertakan tag elemen, potongan src, dan
  jumlah entry lossless. Ini penting karena DevTools tidak ada di build release — toast adalah
  satu-satunya kanal diagnostik.
- **`tools/diag-track-url.js`** — snippet Chrome untuk melihat isi DOM media + daftar request
  lossless, tanpa perlu rebuild.
- Bug sampingan yang ketemu saat refactor: kalau panel nanti memanggil `saveTrack({trackId})` untuk
  track yang TIDAK sedang diputar, kode lama akan mencomot URL lagu yang kebetulan sedang diputar
  (salah track). Sekarang URL hanya dipakai kalau `trackId`-nya cocok, dan kalau tidak ada URL
  maka jalur cache-first yang dipakai.

### Pelajaran

Kalau sebuah nilai bisa datang dari beberapa sumber, **validasi bahwa nilainya benar-benar
berguna sebelum diterima** — jangan terima "ada sesuatu" lalu berharap yang terbaik. Versi pertama
menerima URL apa pun dan akibatnya pesan errornya menyesatkan.
